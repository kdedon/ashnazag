# Quadra 700/900 ROM on a 68060

Question: what must change for the 040 ROM (`420DBFF3`, version $067C, release $15F1) to run under the A/UX Mac environment on a 68060 host? There is no 68060 Mac ROM.

Method: the ROM is disassembled at 0x40800000 as 68040 code, with entry points from the decoded A-trap table (`tools/romdisp.py`, 1,011 entries; format in [rom-dispatch-format.md](rom-dispatch-format.md)) and the ROM header / Foreign OS table. Instructions the 68060 does not implement in hardware are listed, traced back to the traps that reach them, and mapped to ROM resources with `tools/romrsrc.py`. Trap names are from public Inside Macintosh documentation.

Only **user-mode** instructions matter: under A/UX the ROM runs in a user process, privileged instructions (`movec`, `cinv`/`cpush`, SR moves) are emulated by our layer on any CPU, and the hardware managers are replaced by `Patch.067C`. `move16` is implemented on the 68060.

Syntax: the 64-bit multiply is written `mulu.l <ea>,Dh-Dl`; `divsl.l`/`divul.l Dr:Dq` are the 32-bit remainder forms (implemented on the 060). The ROM has no 64-bit divides (`divu.l`/`divs.l` 64/32).

## Findings (39 hits)

| Where | Hits | Kind | Runs under A/UX? |
|---|---|---|---|
| Time Manager (`_InsTime`/`_PrimeTime`, ROM $0AF06) | 1 | `mulu.l D0,D0-D1` | **no**: Time Manager is replaced by `Patch.067C` |
| **FixMath: `_LongMul` / `_FixMul` (ROM $1C2F6, $1C33E)** | 2 | `muls.l (d16,SP),D0-D1` | **yes**, heavily (QuickDraw and applications) |
| Cursor code after `_ObscureCursor` (ROM $283BC) | 1 | `mulu.l D0,D0-D1` | probably not: A/UX supplies its own cursor routines (to verify) |
| **QuickDraw `_MapPt` / `_MapRect` area (ROM $33AA8)** | 1 | `muls.l D5,D6-D0` | **yes** |
| ROM $8D000–$94FFF (not reached from any trap; likely the ROM's 68040 floating-point emulation package, installed as exception handlers) | 10 | `fmovem.x` with a register-held list (8), `movep` (1), `chk2` (1) | **no**: floating-point exceptions go to the host kernel's package, not the ROM's |
| **`PACK 4` (FP68K, FPU version, ROM $0EB1F0)** | 11 | transcendental/`fmovecr`/`fscale`/`fgetexp`, `fScc`, integer | **yes**, when applications use SANE |
| **`PACK 5` (Elems68K, FPU version, ROM $0EEC60)** | 13 | `fmovecr`, `fscale`, `fgetexp`/`fgetman`, `fScc` | **yes**, when applications use SANE elementary functions |

The ROM also carries **non-FPU versions of `PACK 4` and `PACK 5`** ($0E7EF0, $0E9F90) with no FPU instructions.

## What is needed for the 68060

**Option A: host kernel emulation only (no ROM changes).** The 060 host kernel must emulate, for user-mode code:
- 64-bit `muls.l`/`mulu.l` in these forms: `(d16,SP),Dh-Dl` and `Dn,Dh-Dl`. The AMIX 040/060 port only emulates the forms measured in AMIX userland, so these need checking or adding; the full Motorola 060 integer package (ISP) covers them.
- FPU: transcendental functions, `fmovecr`, `fscale`, `fgetexp`/`fgetman`, `flog2`, `fScc` (the 060 floating-point package). The AMIX port includes the full 060 FP package.
- Cost: an exception per `FixMul`/`LongMul`/`MapPt` call, which QuickDraw uses constantly.

**Option B (recommended): patch the instructions in a RAM copy of the ROM, keep A as the safety net.**

Trap-table replacement is not enough: QuickDraw calls these routines directly by address as well as through the trap, and the `_MapPt`-area hit is inside a routine. Instead, run from a RAM copy of the ROM (A/UX's `TBRAM` / `-o ram` mode) and patch the code at startup:

1. Replace each 64-bit multiply with a same-length subroutine call to a helper that computes the 64-bit product from the 060's fast 32-bit multiplies (four partial products):
   - `muls.l (d16,SP),D0-D1` (6 bytes) → `jsr abs.l` (6 bytes);
   - `muls.l D5,D6-D0` (4 bytes) → `jsr abs.w` (4 bytes), with the helpers in a page mapped at **0xFFFF8000** in the Mac process (sign-extended short addresses land there; both hosts give user processes the full address space).
   Cost: about 20–40 cycles per multiply (similar to the 040's hardware instruction) instead of an exception costing hundreds. Catches trap calls, direct calls and inline sites alike.
2. Sites under A/UX: `_FixMul` ($1C33E), `_LongMul` ($1C2F6), `_MapPt` area ($33AA8), and the cursor site ($283BC) if it turns out to be used. Keep the patch as a table of ROM offsets with expected original bytes; refuse to patch a ROM that does not match.
3. SANE: on a 68060, select the ROM's **non-FPU `PACK 4`/`PACK 5`** (pure integer code, no FP exceptions).
4. `Patch.067C` is loaded into RAM by `libmac1_s`, so its `aMicroSeconds` multiply can be patched at load time the same way. System 7.0.1 patch resources would need a resource-load hook; leave them to host emulation unless they prove hot.
5. Leave the Time Manager, cursor (unless used) and ROM FP-emulation hits alone.

**Bigger performance factor**: every Toolbox call is an A-line trap. Handled in user space, each one is a signal round trip (thousands of cycles), far worse than the 060 issue; a kernel fast path (as A/UX's `lineAVector` does) is what makes drawing fast.

**Also check (not ROM):** `Patch.067C` and System 7.0.1 use 64-bit multiply/divide too (`aMicroSeconds` `mulu.l #$411b,d1:d0`; System `ptch` 4/26/32 and `lpch` 20/31 `divu.l`/`divs.l` 64/32). Those need the same treatment: host-kernel emulation, or replacement of the few routines involved.

## Application and System software on the 68060 (no Mac OS patching)

The 68060 raises exceptions for what it does not implement: **unimplemented integer instruction** (vector 61: 64-bit mul/div, `movep`, `cas2`, `chk2`/`cmp2`), **F-line** for unimplemented FPU instructions (transcendentals, `fmovecr`, `fScc`/`fDBcc`/`fTRAPcc`, register-list `fmovem`), **unimplemented effective address** (vector 60) and **unimplemented data type** (vector 55). All reach the kernel, so software needs no patching on disk.

1. **Trap and emulate** (correctness for everything: applications, extensions, System patches, run-time code): Motorola's 060 software packages (integer + FP), either complete in the host kernel for user mode, or hooked by our A/UX-compat driver for Mac processes (under our control). Cost: an exception per execution.
2. **Trap and patch** (speed): on the first exception at a RAM-code address, emulate once, rewrite the instruction in place as a same-length `jsr` to a helper (helpers at 0xFFFF8000 for 4-byte forms), flush caches, resume; later executions run near native. Precedent: Amiga 060 CyberPatcher/OxyPatcher (FPU instructions in applications, including under ShapeShifter). Handle: Segment Loader reloading `CODE` (just repatches); skip read-only ROM, shared text, self-checksumming or data-shared code (emulate instead); only same-length forms; a per-application opt-out list.
3. **Static patches** for known hot code: the ROM (above), optionally `Patch.067C` at load.

Recommendation: 1 in our driver, 2 enabled for Mac processes, 3 for the ROM, plus non-FPU `PACK 4`/`5` on 060. On a 68LC060 report "no FPU" to the Mac side so software uses integer paths. 030 and 040 hosts are unaffected (040 transcendentals already need the 040 FP package).

## Open points

- Confirm the cursor site at $283BC is unused under A/UX.
- Check the full FixMath family (`_FixDiv`, `_FracMul`, `_FracDiv`, `_FixRatio`, `_FracSqrt`) for other 64-bit forms in non-seeded code.
- Measure the cost of option A on a real 060 before deciding how far to go with option B.
